## 2. 저장 구조 — 설계 문서보다 한 단계 더 간 지점

A8-1 설계 문서 §2·§4는 A5·A7과 같은 방식(사람 생성 경로 셋 — `ob-start`·`ptSave`·`savePerson`
새-사람 분기 — 의 `birth` 리터럴에 각각 `self:null`을 넣는 방식)을 그대로 제안했다. 하지만 그
방식은 **정확히 이 프로젝트가 두 번 밟은 사고의 원인**이다:

- A5: `ob-start`·`ptSave`가 `birth.est`를 안 넣어 `undefined`로 굳음 (실측으로 발견, `2026-09-17-A5-시각추정-구현.md`)
- A7: 같은 두 경로가 `birth.dayRule`도 안 넣음 (실측으로 발견, `2026-09-17-A7-자정일주선택.md`)

두 번 다 "경로가 셋인데 하나만 고치고 잊는다"가 원인이었다. 이번엔 `self`를 `birth` 안이 아니라
**노드(`addNode`가 만드는 객체) 레벨**에 두고, 기본값을 **`addNode` 함수 안에서 한 번만** 정했다
(`self:self===undefined?null:self`). `addNode`는 사람을 만드는 **유일한** 함수라 — 저장본을
복원하는 `applySeed`만 기존 값을 명시적으로 넘기면(`self:p.self`), 나머지 세 경로
(`ob-start`·`ptSave`·`savePerson` 새-사람)는 **아무것도 안 고쳐도** 자동으로 `null`을 받는다.

**실측**: 브라우저에서 실제 온보딩으로 "나"를 만든 뒤 `n.self`를 확인 — 첫 생성 시점부터
`null`(undefined 아님). 재발 방지용 `nodeSelfExplicit` 자가진단도 추가했지만(§4), 이번엔 구조
자체가 그 자가진단이 걸릴 일을 막는다.

## 3. §1-ⓐ 시각 검증 — A5 재사용

`estStart(n,{mode:'verify'})`로 열면 질문 엔진·가점·종료조건은 A5와 **완전히 같은 코드**를 타고,
`estFinish` 뒤 결과 화면만 `renderEstVerifyResult()`로 갈라진다:

- 답으로 좁힌 후보(동점이면 후보 전체)에 실제 입력 시각의 칸이 들어 있으면 **같음**(D-5).
- 아니면 **다름**(D-6) + 꼬리 문장(D-7).
- **`birth.est`는 안 건드린다** — 검증은 한 번 보고 끝나는 기능이고, 시각을 아는 사람에게
  추정값이 생기면 A5 안내(추정 배지 등)와 섞인다(설계 §1-ⓐ 그대로).

동점 폴백(A5는 사람이 직접 고르게 함)은 검증에서는 생략했다 — 검증은 값을 하나로 확정할 필요가
없고, 알고 있는 시각이 후보 집합 안에 있는지만 보면 된다[그냥 진행함].

### 5-1. 실제 온보딩 → 테스트 → 저장
```
온보딩으로 "테스트나" 생성(1990-01-01, 여, 시각 모름)
패널에 「스스로 본 모습」 덩이 — 기본 펼침, "테스트 하기" 버튼
시트 열림 → 안내 → 10문항(A/B 번갈아 답) → 상황 "일" 선택
→ 결과: SELF(비겁) + MATCH("사주에도 이 기운이 가장 많습니다…") + 상황 줄("일에서는…")
저장 → n.self = {answers:10건,counts:{비겁:4,식상:3,재성:0,관성:1,인성:2},situation:'일',at:…}
localStorage 저장본과 완전 일치
```

### 5-2. 새로고침 · 정보 수정 후 유지
```
새로고침 → n.self 그대로(값 동일)
정보 수정 폼에서 이름만 "테스트나수정"으로 바꿔 저장 → self 그대로(메모리·저장본 둘 다)
```
`savePerson`은 `n.birth`만 재할당하고 `n.self`는 건드리지 않는다 — A8-1 §2가 "확인 필요"로
남긴 대목을 코드로 확인했다(더 손댈 것 없음).

### 5-3. 상황에 맞는 코너 자동 펼침
```
situation='일' 저장 후 패널 확인 → "어울리는 일" 코너만 펼쳐짐(내용 그대로 보임),
"돈 스타일"·"관계 스타일"·"힘이 되는 기운"은 계속 접힘
```

### 5-4. 지우기
```
selfClear(n) 호출 → n.self === null, 저장본도 null
패널이 "테스트 하기" 최초 화면으로 되돌아감
```

### 5-5. 시각 검증
```
같은 사람 시각을 12:00(정오)로 정확히 입력 → 저장 → 사주 표 아래 "확인해 보기" 버튼
클릭 → estsheet가 "…의 시각이 맞는지 확인" 제목으로 열림(추정 모드와 다른 제목)
"낮" → 문항 1개 답 → 결과: "답으로 좁힌 시각도 오시(11–13시)입니다. 알고 계신 시각과 같은 쪽입니다."

  + "시각이 확실하다면, 답이 요즘 모습 쪽에 더 가깝다는 뜻일 수 있습니다."
```
