# C4 — a줄 조립 구조 변경 + 관계 패널 합충 딱지 제거 [2026-09-08]

**세 줄 요약**
`relLead()`를 합충이 있을 때 "당신과 …사이입니다. 당신에게는 …고요." 두 문장으로 떼어냈고,
상관 조각을 "뒷심이 짧은 재간둥이"로 줄였다. 관계 패널의 합충 딱지(`.hcchip`)는 렌더에서 뺐다 —
`hcChipHtml()`이 카드와 공용이 아니라 이 패널 한 곳에서만 쓰이던 것을 실측으로 확인했다.

## 착수 전 실측 (지시와 대조)
1. `relLead(g,hcKind)` — 3265행. 이전 방식: `'이 사람은 당신에게 '+(hp?hp+' ':'')+REL_PIECE[g]+' 같은 존재입니다.'` — 지시문 설명과 일치.
2. `REL_PIECE[3]`(상관) — `'재주 많고 뒷심은 짧은 재간둥이'` — 지시문 예시와 일치.
3. **딱지 렌더는 관계 패널·카드 공용이 아니었다.** `hcChipHtml()`(2779행)을 호출하는 곳은
   `index.html` 전체에서 **10065행 관계 패널 렌더 한 곳뿐**이었다. 카드(`cardText()`, 2334행)는
   `hapChung()`을 직접 불러 `t.chip`을 따로 만들고 `hcChipHtml`을 아예 안 쓴다.
   → 분기표의 "공용이면 관계 패널 호출만 뺀다"가 아니라 애초에 전용이라, **`hcChipHtml()` 함수
   자체를 지워도 카드는 안 깨진다.** 다만 지시문이 "함수는 남긴다(hapChungOf)"만 명시했고
   `hcChipHtml`은 언급이 없어, **되돌릴 가능성을 남기려고 삭제하지 않고 미사용 상태로 남겼다**
   (판단해서 정한 것 — 삭제해도 됐지만 보수적으로 남김).

## 바뀐 파일
`index.html`만 (C4 작업분 미커밋 — 이전 C 회차분과 함께 쌓여 있음)
- `relLead(g,hcKind)` — 합충 있음/없음 두 갈래로 재작성
- `REL_PIECE[3]`(상관) — `'재주 많고 뒷심은 짧은 재간둥이'` → `'뒷심이 짧은 재간둥이'`
- `blk()` 시그니처에서 `other,hc` 매개변수 제거, `.nickname`에서 `${hc||''}` 삭제
- `hcA`/`hcB`(`hcChipHtml()` 호출 두 줄) 삭제, 호출부(`t1=blk(...)`) 인자 축소

## 남는 미사용 코드 (지웠으면 보고에만 적으라는 지시에 따라 삭제하지 않음)
- `hcChipHtml()` 함수(2779행) — 이제 호출하는 곳이 없다.
- `.hcchip`/`.hcwhy` CSS(251~264행) — 지시대로 CSS 파일(같은 index.html 안 `<style>`)은 건드리지 않았다.
- `wireHapChung()`(2787행 부근, `.hcchip` 클릭 바인딩) — 대상 요소가 안 생기므로 사실상 공회전.

레이아웃은 안 깨졌다 — 딱지가 없어도 `.nickname` 줄은 별명 텍스트만 남아 자연스럽다(분기표의
"깨지면 보고" 케이스 해당 없음).

## 검증
- 40개(십신 10 × 합충 없음/chung/ganhap/yukhap) `relLead()` 실제 호출 — **빈 문자열·undefined 0건**.
- 합충 없음 10개를 C3 목록과 대조 — **상관 1개만 다르고 나머지 9개는 한 글자도 안 다름**(지시대로 정상).
- 자가진단 **58/58 통과**. 콘솔 오류 **0건**.
- 관계 패널 실제 렌더 확인 — `.hcchip` 요소 **0개**, `.nickdesc` 문장 정상 출력.
