# U34 — 빈 성별·시각 먼저 묻기 [2026-09-20]

- 실행 모델: Opus 5 — 작은 UI 흐름 추가라 조금 과함. 다음(지나온 길 + 답으로 보정)은 설계·문장이 커서 [권장] 같은 급.
- [비용 수준: 하~중 — 함수 6개 + 패널 한 줄 + 폰 크기 실제 클릭 확인]
- 사용자: "권장대로 빈 성별 시각 묻기 진행하자" (계기: 「나」의 성별이 비어 대운이 안 나왔다)

## 무엇
- **인물 패널 맨 위(이름·생일 바로 아래)** 에 빈 칸만 묻는 상자:
  - 성별: 「남」「여」 한 번 누르면 저장 → 10년 흐름·연애·자식 풀이가 바로 열린다.
  - 태어난 시각: 시각 입력 + 「저장」 · 「몰라요 — 추정해 보기」(기존 시각 추정으로) · 「몰라요」(이 기기에서는 다시 안 묻는다 — 저장본에는 안 넣는 기기 편의).
  - 추정해 둔 시각이 있으면 시각은 묻지 않는다.
- **앱을 열 때 「나」에 빈 칸이 있으면 한 번(세션당)** 안내 — 「지금 넣기」(내 패널로) · 「나중에」. 다른 안내가 떠 있으면 덮지 않는다.
- 저장은 `patchBirth` — 수정 시트와 같은 뒷정리(일간·지도·이름표·궤도·고리·저장).
- 「궁금한 것」 안의 옛 「성별 넣기」 안내는 지웠다(한 패널에 같은 안내 두 번 금지).

## 실측 (폰 375×812, 저장 끈 채 메모리에서)
- 앱 안내 → 「지금 넣기」 → 내 패널에 상자 두 줄.
- 「남」 → 성별 저장, 대운 열림, 상자 한 줄(시각만).
- 시각 17:50 저장 → 생일 줄 "17:50 (유시)", 여덟 글자 丙寅 辛丑 壬午 己酉, 신약, 평생 흐름 나타남, 상자 사라짐.
- 다른 사람에서 「몰라요」 → 상자 두 줄 → 한 줄, 다시 안 묻는 목록에 들어감.
- 로컬 저장본은 그대로(저장 끔 확인). 자가진단 **120/120**(missingAsk 추가).
- 로컬 사본에서는 my-data.js 안내가 먼저 떠서 앱 시작 안내가 양보한다 — 배포 주소에는 그 안내가 없다.

## 그냥 진행함
- "몰라요"는 기기에만 기억한다 — 저장 형식을 바꿀 만큼의 정보가 아니고, 다른 기기에서는 다시 물어도 무해하다.
- 표 입력(붙여넣기)·첫 등록 화면은 이미 성별 필수라 손대지 않았다.

## 실기기 재확인 목록
- 폰(배포 주소)에서 앱을 열었을 때 「나」 안내가 한 번 뜨는지
- 폰에서 시각 입력 칸(시계 선택기)이 잘 열리고 저장되는지 — iOS·안드로이드 선택기 모양이 다르다
- 성별·시각을 넣은 뒤 「나」 패널의 세기·어울리는 일·평생 흐름이 본인에게 맞는지
