## 사전 실측 (2026-09-08, 지시문 작성 중 확인 — ⑫에서 재확인 불필요)

**1) 이름은 이미 코드에 있다.** `cardText(a,b)`의 `side=(x,y,g)=>({dir:x.name+'에게 '+y.name+...})`가
이미 `x.name`/`y.name`을 쓴다. 방향 라벨은 새 데이터 배관 없이 `x.name+'가 보는 '+y.name` 식으로 바로 만든다.

**2) 카드 5색 배정 규칙 = 일간(日干) 오행 기준이다.** `side()`의 `elem:cardElem(y.stemIdx)`,
`cardElem(stemIdx)=floor(stemIdx%10/2)` → 甲乙=목 / 丙丁=화 / 戊己=토 / 庚辛=금 / 壬癸=수.
즉 **그 카드에 그려지는 사람(상대)의 일간**이 색을 정한다. 관계 오행(십신)이나 나열 순서가 아니다.
왼쪽 카드는 b의 일간, 오른쪽 카드는 a의 일간을 쓴다.

**3) 지금 명패는 이미 3줄이다.** 위에서부터 `dir`(작게, "A에게 B는") / `nick`(크게, 별명) /
`pillar`(작게, 일주 간지 두 글자, 예 庚申). ⑫에서 넣을 3요소와 자리 수가 같으므로 **일주 간지를
어떻게 할지가 미정 사항**이다(아래 「Teo 결정 필요」 1번).

### 4. 같이 처리할 미해결 4건

**(1) [⑪] 글자 세로 중앙이 실측이 아니다.**
`cardPlan()`의 `ty` 계산에 `+3` 보정 상수가 들어가 있다(⑪에서 원인을 못 밝히고 실측값으로 때움).
이번에 요소가 3개로 늘고 글자 줄 수가 바뀌므로 **다시 틀어진다.** 보정 상수를 지우고 원인을 잡을 것.
의심 지점: 가운데 별명 줄(줄간격 1.22)의 실제 잉크 위치가 계산한 줄 상자보다 아래로 치우침.
`measureText().actualBoundingBoxAscent/Descent`를 **모든 줄에 대해** 재서 잉크 상자를 만들고,
그 상자의 중심을 명패 중심에 맞추는 방식으로 바꾼다. 목표: 5색 전부 ±1px, **보정 상수 0.**

**(2) [⑪] 명패 박스 경계를 측정하지 못했다.**
검증 스크립트가 프레임-로컬 좌표(`fit.whiteBottom`)와 캔버스 절대 좌표(`band.y+band.h`)를 섞어 비교해
`false`가 나왔다. 스크립트를 고쳐(`cy`를 더해 좌표계를 맞춰) **박스 위 경계 = 그림 아랫변**,
**박스 아래 경계 = 흰 영역 아래 경계**를 5색 전부 좌표로 확인해 표로 보고할 것.

**(3) [⑪] 자가진단 실패 1건이 언제 사라졌는지 불명.**
⑨에서 57개 중 `nodeLabelZoom` 1건이 실패했는데 ⑩·⑪에서는 58/58로 통과했다.
저절로 통과한 것인지(타이밍 문제) 검사가 느슨해진 것인지 확인할 것.
확인법: 해당 검사 코드를 읽어 판정 조건이 바뀌었는지 `git diff`로 보고, 연속 5회 돌려 재현율을 적을 것.
**검사를 고치지는 말고 판정만 보고한다.**

**(4) [⑩] 액자선의 정체가 코드인지 원본 PNG인지 미확정.**
⑩에서 `op:'line'`(오방색 가는 선)을 지워 화면에서는 사라졌지만, **원본 PNG 가장자리에도 흰/검은 테가
있는지는 확인하지 않았다.** 있으면 그림을 교체할 때 재발한다.
확인법: `assets/card-b/pic-01~10.png` 10장의 네 변 가장자리 3px을 픽셀로 훑어
(a) 흰색(RGB 모두 245 이상) 또는 (b) 검정(모두 15 이하)이 연속으로 몇 px 있는지 세어 표로 보고할 것.
**있으면 그리기 단계에서 몇 px 잘라낼지 제안만 하고 이번 회차에 자르지는 말 것.**
