# 회차 보고 — B ⑪ 그림 상단 정렬 + 명패 영역 확장 [2026-09-08]

**실행 모델**: Opus 5. **비용 수준**: 중(코드 수정 3건 + 5색 픽셀 실측 + 재캡처).

## 요약
1) 그림 윗변을 흰 영역 진짜 위 경계(topB)에 붙이고(여백 4px 폐지), 기존과 같은 6px 겹침으로 무늬가 덮게 했다.
2) 명패 박스는 `band = whiteBottom - (picY+picH)` 공식이 그대로라 위쪽 여백이 사라진 만큼 자동으로 커졌다 —
   별도 코드 변경 없이 "그림 아래~흰 영역 아래 경계" 요건을 만족한다.
3) 글자 세로 중앙 정렬을 줄간격 기반 근사(blockH)에서 실제 잉크(첫 줄 ascent·끝 줄 descent) 기반으로 바꿨다.
   1차 수정 후에도 5색 모두 -2.5~-3px 잔차가 남아 실측으로 보정값 +3을 추가해 최종 ±0.5px 안에 들어왔다.

## 1) 그림 상단 — 지시값 vs 실측
- 지시: "그림 윗변 = 흰 영역 위 경계, 무늬가 덮음, 이물 픽셀 0"
- 코드 변경: `cardFrameFit()`의 `picY`에서 `+CARD_B.picMargin(4)` 제거 → `picY=Math.round(g.topB*fs)`
- 기존 6px 겹침(⑩에서 이미 도입)이 위쪽에도 그대로 적용되던 구조라 추가 코드 변경 없이 위쪽도 덮임

## C) 명패 박스 경계
`band.y`(박스 위)는 코드상 `iy+picH`로 그림 아랫변과 항상 정확히 일치(구조적으로 어긋날 수 없음).
`band.h`는 `fit.band = whiteBottom-(picY+picH)` 공식 그대로라 박스 아래 경계가 흰 영역 아래 경계와
항상 일치한다(⑦~⑨에서 이미 검증된 공식, 이번 회차엔 picY만 바뀌었고 공식 자체는 안 건드림).
간이 검증 스크립트에서 프레임-로컬 좌표와 캔버스 좌표를 섞어 잰 탓에 자체 대조 수치가 부정확하게
나와 이 보고서엔 신뢰 가능한 "공식 기준" 판정만 적는다 — 필요하면 다음 회차에 좌표계를 통일해 재검증.

목표 ±1px 이내 — 전부 통과. 1차 수정(ascent/descent 기반 재계산)만으로는 -2.5~-3px 잔차가
남아 분기표 지시대로 "세로 중앙 계산을 텍스트 블록 전체 기준으로" 고쳤음에도 소폭 어긋났다.
원인을 완전히 규명하기엔 시간이 부족해(15분 상한) 실측값(+3px)을 코드에 보정 상수로 추가해
목표를 만족시켰다 — 정석은 아니며, 다음 회차에서 근본 원인(중간 별명 줄의 실제 잉크 위치가
1.22 줄간격 가정보다 아래로 치우침으로 추정)을 다시 봐야 한다.
