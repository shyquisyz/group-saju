## 1. 무엇을 정해야 하나 (이미 정해진 것 / 이번에 정할 것)

**이미 정해져 있어 다시 안 묻는 것**
- 인물 ≠ 계정 — 등록한 사람은 비회원 인물이고, 본인이 가입하면 클레임한다(HANDOFF §7.1).
- 나 = 유일한 항성, 나 삭제 금지, 나 없는 그룹 금지(§7.2).
- 그룹 생성은 무제한·무료(§8.1).
- 토큰은 **건별 원장**, 잔액만 두지 않는다. 환불 규정은 설계 때 함께(§8.1).
- 미가입자에게 "누가 당신을 등록했다" 알림 금지(§8.2).
- 결제 결과·잔액을 브라우저 저장만으로 관리하지 않는다(검토서 §24).
- 비밀키를 화면 코드에 넣지 않는다, 서버에서 권한 검사(검토서 §18.3).

**이번에 정할 것** — 스택·호스팅, 로그인 수단, 데이터 구조, 동기화 규칙, 토큰 원장 구조, B1~B4 쪼개기.

## 4. 데이터 구조 (서버)

```
profiles        계정 1행. id = 인증 사용자 id
people          인물. owner_id(누구의 은하) · local_key(지금 node.id) · name · is_me
                · birth(json: 지금 birth 그대로) · self(json: A8의 self 그대로)
                · claimed_by(가입한 본인 계정, 없으면 null) · visibility('private' 기본)
                · expires_at(기간 한정 등록용, 지금은 null) · created_at · updated_at · deleted_at
                  제약: (owner_id, local_key) 유일 / 계정마다 is_me 정확히 1명
groups          owner_id · local_key · name · type · parent_id · order_index · 시각들 · deleted_at
group_members   group_id · person_id
token_ledger    id · account_id · delta(+/-) · kind · person_id · note · idem_key(유일) · created_at
                  → 수정·삭제 불가. 잔액 = delta 합계(뷰)
(B2) invite_codes   code_hash · person_id · created_by · expires_at · used_by · used_at · revoked_at
(B3) connections    두 인물 · 두 계정 · 상태 · 시각
(B4) group_invites  group_id · code_hash · 만료 · 최대 인원 · 승인 방식
```

- **관계선(links)은 서버에 안 둔다 [권장]** — 지금도 불러온 뒤 그룹에서 다시 만든다(`serializeState` 주석).
- **birth·self는 json 한 칸** — 화면 코드와 같은 모양을 그대로 옮겨 변환 코드를 두 벌 만들지 않는다.
  계산은 지금처럼 화면에서 한다(서버는 저장만).
- **지운 것은 `deleted_at`으로 표시만** — 원장이 그 인물을 가리키고 있어서다. 계정 삭제 요청 때는
  이름·생년월일을 실제로 지우고 원장에는 id만 남긴다(개인정보 삭제와 기록 보존을 같이 만족).
- **권한(RLS)**: people·groups·group_members는 `owner_id = 로그인한 나`만 읽기·쓰기.
  token_ledger는 **읽기만** 허용, 쓰기는 서버 함수만.

## 6. 동기화 규칙

1. **로그인 전** — 지금과 똑같다. 저장은 브라우저에만, 문구도 그대로.
2. **처음 로그인할 때(이 기기에 데이터가 있으면)**
   - 계정이 비어 있으면 → **전부 올린다.** 올린 사람들은 **토큰을 안 뗀다**(원장에 `import` 0으로 기록)
     [권장] — 공개 전이라 올릴 사람은 사실상 운영자·테스터뿐이다.
   - 계정에 이미 데이터가 있으면(다른 기기) → **"이 기기 데이터 / 계정 데이터" 중 하나를 고르게** 한다.
     합치기는 1차에서 안 한다 [권장]. 어느 쪽이든 **덮이기 전 상태를 `groupsaju:save:prev`에 남긴다**
     (지금 백업 불러오기와 같은 안전망).
3. **로그인 후** — 서버가 정본, 브라우저 저장은 빠른 첫 화면용 캐시.
   - 고치면 화면에 먼저 반영하고 서버에 보낸다. 실패하면 되돌리고 알린다.
   - **오프라인에서는 고치기를 막는다 [권장]** — 두 기기 충돌 처리 엔진을 만들지 않기 위해서다.
     보기는 캐시로 된다.
   - 두 기기가 같은 행을 고치면 나중 것이 이긴다(`updated_at`). 드문 경우라 1차는 이걸로 충분하다.
4. **로그아웃** — 이 기기의 캐시를 지운다 [권장](공용 기기 보호). 데이터는 계정에 남는다.
5. **문구 4곳 교체** — 로그인 상태면 "이 브라우저에만 / 어디로도 전송되지 않습니다"가 **거짓이 된다.**
   로그인 상태에 따라 문구를 바꾼다(1796·1894·1958·9114행).
6. **백업 파일(내보내기·불러오기)은 그대로 둔다** — 계정이 있어도 "내 데이터를 파일로 갖고 있기"는
   유효하다. 불러오기는 로그인 상태에서 "계정 데이터를 이 파일로 바꾸기"로 동작한다.

## 7. 토큰 원장 — 구조는 지금 정하고, 값은 D에서 정한다

**원장 사건 종류(kind)**: `signup_grant`(가입 지급) · `referral`(추천) · `beta_grant`(테스터 지급) ·
`import`(첫 업로드, 0) · `register`(등록) · `register_temp`(기간 한정 등록) · `edit_birth`(출생정보 수정) ·
`delete_refund`(삭제 환급) · `purchase`(결제, D) · `refund`(결제 환불, D) · `admin_adjust`(운영자 조정, 사유 필수).

**서버 함수가 한 번에 하는 일** — 예: 인물 등록 = ① 잔액 확인 ② 인물 행 추가 ③ 원장 행 추가를
**하나의 트랜잭션**으로. 같은 요청이 두 번 와도 `idem_key`로 한 번만 처리(검토서 §16 "중복 처리 금지").

**값(몇 토큰인가)은 세 안이 있다** — 이번에 확정하지 않는다 [권장]. 결제가 D라서, B에서는 실제로
돈이 오가지 않는다. B에서는 **구조와 규칙 스위치만** 만들고, 값은 표 한 곳(서버 설정 표)에 둔다.

| 행위 | HANDOFF §8.1(08-28) | 검토서 §11(초안) | 사용자 안(09-17) |
|---|---|---|---|
| 등록 | 1명분 | 3 | 4(영구) / 2(일주일) |
| 생년월일 수정 | 1/2~1/3명분 | 1 | 1 |
| 삭제 | — | — | **+1 환급** |
| 가입 지급 | 3명분 | 본인+2 무료 | — |

**B 기간 운영 [권장]**: 가입 지급은 "본인 + 2명 무료"(세 문서가 모두 같은 방향)로 두고, 테스터에게는
`beta_grant`로 넉넉히 준다. 이렇게 하면 원장 로직이 실제로 돌면서도 테스트가 막히지 않는다.
사용자 안의 환급 규칙은 원장 구조상 "등록 −4 → 삭제 +1"로 토큰이 늘어나는 경로가 없다(확인 완료) —
단 **기간 한정 등록(2)에는 환급을 두지 않아야** "일주일 2 / 영구 실질 3" 차이가 유지된다.

- 각 서비스의 "리디렉션 주소"에 넣을 값은 B1b에서 정확히 적어 드립니다.

**결정은 아니지만 알고 계셔야 할 것 — 개인정보 [확인 필요]**
서버가 생기면 **다른 사람의 이름·생년월일을 우리가 보관하게 됩니다.** 지금은 "브라우저에만 있다"가
방패였는데 그게 사라집니다. 공개(뿌리기) 전에 **개인정보 처리방침**과 "타인 정보 등록" 안내·동의 문구가
필요하고, 법률 확인을 권합니다. 테스트 단계(운영자·지인)에서는 막히지 않습니다. 완화책은 설계에
넣었습니다 — 실명 대신 별칭 권장, 삭제 시 실제 삭제, 원문은 본인 외 비공개.

## 9. B1~B4 쪼개기 (결정 뒤)

| 회차 | 내용 | 모델 [권장] |

## 그냥 진행함
- **B0를 "선택지 + 권장안" 문서로 끝냈다.** 검토서 §23이 스택·로그인을 임의 확정 금지로 묶어 둔 항목이다.
- **토큰 값을 확정하지 않았다.** 결제(D)가 마지막이라 B에서는 구조만 필요하다 — 값 결정은 D 직전에
  하는 편이 실제 사용 기록을 보고 정할 수 있다.
- **`claimedBy`·`visibility` 선반영을 B1c로 미뤘다**(§5, 근거 있음).
- **외부 서비스 조건은 웹 검색으로 확인한 것만 적었다.** Firebase 요금은 조사하지 않았다(권장안이 아니라서).
