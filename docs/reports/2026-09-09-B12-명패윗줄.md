## A. 명패 맨 윗줄 문구

`cardText()`의 `dir` 조립을 `cardDirLabel(x,y)`로 뺐다. `x`가 보는 쪽, `y`가 그려지는 쪽이다.

```
x.isMe  → '내가 보는 ' + y.name
y.isMe  → x.name + particle(x.name,'이가') + ' 보는 나'
그 외   → x.name + particle(x.name,'이가') + ' 보는 ' + y.name
```

조사는 기존 헬퍼 `particle()`을 그대로 썼다(받침 있으면 '이', 없으면 '가').

| 경우 | 이전 | 이후 |
|---|---|---|
| 본인 낀 · 왼쪽 | 구성원Z에게 구성원B는 | **내가 보는 구성원B** |
| 본인 낀 · 오른쪽 | 구성원B에게 구성원Z는 | **구성원B가 보는 나** |
| 본인 안 낀 · 왼쪽 | 구성원A에게 구성원D는 | **구성원A가 보는 구성원D** |
| 본인 안 낀 · 오른쪽 | 구성원D에게 구성원A는 | **구성원D가 보는 구성원A** |

(보고서의 이름은 전부 합성 인물이다 — 실제 인물 데이터는 캡처·표에 쓰지 않았다.)

**넘침 없음.** 자가진단의 긴 이름 시험(21자 `가나다라마바사…`)에서도 `cardWrapLong` 통과,
명패 폭을 넘긴 줄 **0개**. 실제 5색 카드에서도 윗줄은 전부 1줄(10자)로 들어갔다.

## C. 글자 세로 중앙 정렬 — 보정값 0

### C-1. +3의 정체

⑪은 첫 줄 ascent와 마지막 줄 descent만 재고 남는 −2.5~−3px을 `+3`으로 때웠다.
이번에 **세 블록의 모든 줄**을 재는 방식으로 바꾸고 `+3`을 지운 뒤 측정하니 **세로 차이가 0~1px**로 들어왔다.
즉 **+3은 잔차가 아니라 ⑪의 측정이 틀려서 생긴 헛값**이었다(그때 프레임 안 좌표와 캔버스 좌표를 섞었다).
계산식 자체는 ⑪ 것과 수학적으로 같은 답을 낸다 — 바뀐 것은 **모든 줄을 훑어 min/max를 잡는다**는 점과,
`rel` 누적을 실제 그리기 루프(`put()`)와 **같은 식**으로 짜서 구조적으로 어긋날 수 없게 한 점이다.

측정법 — 카드 계획(`cardPlan`)의 글자 명령만 흰 캔버스에 그려 잉크만 남기고,
보이는 띠 상자(`band.x+6 … band.x+band.w−6`, `band.y … band.y+band.h−6`) 안에서
어두운 픽셀의 최소·최대 x·y로 잉크 상자를 잡아 중심을 비교했다. **전부 캔버스 절대좌표다.**

| 오행 | 왼쪽 세로차 | 왼쪽 가로차 | 오른쪽 세로차 | 오른쪽 가로차 |
|---|---|---|---|---|
| 목 | **0.0** | 0.5 | 0.5 | 0.5 |
| 화 | **0.0** | 0.0 | 0.5 | 1.5 |
| 토 | **1.0** | 1.5 | 1.0 | 0.5 |
| 금 | **0.5** | 0.5 | 0.5 | 1.0 |
| 수 | **0.5** | 0.5 | 1.0 | 0.5 |

**세로 10칸 전부 ±1px 이내, 보정값 0.** 가로는 최대 1.5px인데, `textAlign='center'`가
글자 폭(advance)을 기준으로 가운데를 잡고 실제 잉크는 좌우 여백(side bearing)이 달라서 생기는 차이다.
목표가 세로였으므로 가로는 손대지 않았다.
