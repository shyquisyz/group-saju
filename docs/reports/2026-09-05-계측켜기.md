## 2. 실측 결과

**형식 일치**: 공식 스니펫(`<script data-goatcounter="https://코드.goatcounter.com/count" src="//gc.zgo.at/count.js">`)이
가리키는 주소와 우리 코드가 직접 부르는 `/count` 픽셀 주소가 **같은 형식**이다. 공식 문서(pixel 절)가
스크립트 없이 `<img src="https://코드.goatcounter.com/count?p=...">`를 직접 쓰는 것을 별도의 정식 방법으로
설명하고 있어, 우리가 스크립트를 안 싣고 픽셀만 쓰는 지금 방식은 스니펫을 바꿔 끼운 것이 아니라
처음부터 그 스니펫이 향하는 곳과 같은 곳으로 보내는 **다른 통로**다. 코드를 바꿀 이유가 없었다 —
`SITE` 값만 채우면 됐다.

**로컬 실측**(8903, 예시 은하로 부팅 → 저장본 지우고 새로 열어 처음부터): 첫 방문 → 등록 → 둘째 추가 →
카드 생성 → 공유 → 이미지 저장을 차례로 실행. 요청 6건이 실제 사이트(`shyquisyz.goatcounter.com`)로
나갔고 **전부 200**.

| 사건 | 요청 | 상태 |
|---|---|---|
| first-visit | `?p=first-visit&e=true&rnd=…` | 200 |
| me-registered | `?p=me-registered&e=true&rnd=…` | 200 |
| first-other-added | `?p=first-other-added&e=true&rnd=…` | 200 |
| card-created | `?p=card-created&e=true&rnd=…` | 200 |
| share-done | `?p=share-done&e=true&rnd=…` | 200 |
| image-saved | `?p=image-saved&e=true&rnd=…` | 200 |

6건 URL을 전수 검사 — `p`(사건 이름)와 `e`(사건 표시)와 `rnd`(캐시 방지 시각)뿐이다. 이름·생년월일·
그룹명·경로 등 어떤 개인 식별 정보도 없다.

**배포 확인**: 푸시 후 배포 파일의 sha256 앞 16자리가 HEAD의 그것과 일치(`e293fb7f08775844`, 폴링
6회·약 48초 만에 반영). 배포 주소(사용자 실데이터, 사람 9명 보관 중인 브라우저)에서는 **저장본을
전혀 건드리지 않고** `track('first-visit', true)`를 콘솔로 직접 불러 같은 코드 경로를 확인 —
`https://shyquisyz.goatcounter.com/count?p=first-visit&e=true&rnd=…` **200**. 실행 전후 `localStorage`의
저장본과 사람 수(9)는 그대로였다(온보딩 화면을 누르지 않았고 저장 관련 함수도 부르지 않았다).

**허용 도메인 설정 확인** — 지난 보고의 [미확인] 항목. 공식 문서·검색 결과로 확인: GoatCounter에는
방문·사건 데이터를 **보낼 수 있는 도메인을 제한하는 설정이 없다.** "Settings → Sites that can embed
GoatCounter"라는 항목이 있지만, 이건 **대시보드 화면 자체를 iframe으로 끼워 넣는 것**을 허용할
도메인을 정하는 것이지, 픽셀·스크립트가 데이터를 보내는 것과는 무관하다(그 목적의 설정은 기본이
"허용 안 함"이지만, 우리가 쓰는 것은 그 기능이 아니다). 즉 **첫 화면 가입 단계에서 도메인을 따로
등록할 필요가 없다** — 사이트 코드만 있으면 어디서 보낸 픽셀이든 그 코드의 대시보드에 쌓인다.
