# 회차 보고 — B 3g 카드 미리보기 폭 우선 [2026-09-06]

**실행 모델**: Claude Fable 5.1.
**적정성**: 코드는 몇 줄이지만 "왜 3f 뒤에도 좁았나"를 실측으로 좁혀야 했다(원인이 지시의 추정과 달랐다). **적정했다.**
**다음 회차 모델 [권장]**: 실기기 확인 반영이면 Sonnet 5.

**비용 수준**: 중(지시문과 일치) — 렌더 실측 2건 + 원인 재진단.

## 0. 착수 전 · 어긋난 지점

- `git fetch` 후 `origin/main...main` = `0 0`.
- **지시의 추정("높이 우선 계산 때문")과 실제가 달랐다.** 3f의 `syncCardPrevCap`은 이미 폭 100%를 먼저 잡고 남는 높이가
  모자랄 때만 줄이는 구조였는데, 그 값과 무관하게 캔버스가 293px였다. 실측하니 **3f에서 `#cardsheet .cardprev`의
  `max-height:none`을 지운 탓에 일반 규칙 `.cardprev{max-height:calc(var(--vvh)*.46)}`가 박스를 368px(=800×.46)로
  누르고**, 그 안에서 캔버스가 4:5로 맞춰지며 293px이 된 것이었다(3f 실측이 이 케이스를 못 잡은 이유: 3f는 캔버스가
  아니라 박스의 컴퓨티드 폭을 읽은 자리가 있어 박스 폭만 보고 통과시켰다). 지시의 정의(폭 100%·높이 폭×5/4·높이 축소 제거)는
  그대로 적용했고, 여기에 **원인인 `max-height:none` 복구**를 더했다 — 이것 없이는 정의를 적용해도 같은 증상이 남는다.
- 로컬 확인 중 8910 origin의 `localStorage`에 **실인물 저장본**(사용자의 이전 로컬 테스트로 추정)이 있어 시트에 실명이
  떴다. 갈무리하지 않았고 저장본은 읽기만 했다. 새 포트 8931로 옮겨 데모 데이터로 확인했다.

## 1. 바뀐 것 (`index.html`)

- `#cardsheet .cardprev{…max-height:none…}` 복구.
- `syncCardPrevCap()`: 남는 세로 공간 계산(interior·othersH, 숨기고 재기)과 높이 기준 축소를 **제거**. `--cardprev-w = 모달 내용 폭`,
  `--cardprev-h = 폭 × 1350/1080`만 넣는다. 열 때 + `viewportResync`(리사이즈·orientationchange)에서 재계산은 유지.
- 모달이 뷰포트보다 길면 `.sheet{overflow-y:auto}`(기존)로 안에서 스크롤.

## 3. 실패·보류 · 실기기 재확인

- 시트가 길어지는 PC 낮은 창(800)에서는 카드가 뷰포트를 넘어 스크롤이 생긴다 — 정의 3번대로 허용.
