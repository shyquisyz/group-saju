# U30 — 호칭 칸 + 가족 그룹 자동 제안 · 적응형 배율 [2026-09-20]

- 실행 모델: Fable 5.1 — 저장 형식 변경(v8)과 폼·이름표·패널 세 곳을 잇는 회차라 적정. 다음 회차(U27 중심 바꿔 보기)는 3D 카메라·패널 연동이라 [권장] Fable 5.1 유지.
- [비용 수준: 중 — 저장 변환 1건 + 폼·저장·이름표·패널 4곳 + 브라우저 실측(폼 저장 흐름·배율 강제 전환)]
- 사용자: "권장대로 적응형 배율을 넣고 호칭 칸 진행하자" (U29 보고의 결정 1건 + U16 때 확정한 "호칭 칸 + 가족 그룹 자동 제안 만든다")

## 1. 적응형 배율 (U29-2)
- **무엇**: 폰 GPU가 느리면 화면 배율을 2 → 1.5 → 1로 자동으로 낮춘다. 부팅 4초 뒤부터 3초 동안 프레임 간격을 모아 **중앙값이 30ms를 넘으면**(33fps 미만) 한 단계 낮추고 2초 뒤 다시 잰다(최대 두 단계). 100ms 넘는 간격은 GPU가 아니라 CPU 멈춤이라 뺀다.
- **어디**: `adaptTick`(렌더 루프 첫 줄) · `adaptPR`(renderer 선언 옆) · 살아 있는 초상 캔버스도 같은 배율.
- **실측**: 데스크톱 중앙값 16.7ms → 아무 일 없음(배율 2 유지). 간격 40ms를 80개 강제로 넣어 돌리니 2 → 1.5(캔버스 750×1624 → 562×1218) → 1(375×812)까지 내려가고 세 번째는 멈춤(steps 2). 블룸 컴포저 배율도 같이 바뀜(`composer._pixelRatio` 1.5), 렌더 예외 없음.
- **못 잰 것**: 실제 폰에서 몇 단계 내려가는지. 콘솔에 `[적응형 배율] 프레임 중앙값 …ms → 배율 …`이 찍힌다.

## 2. 호칭 칸 (U30)
- **저장**: `SAVE_VER` 7 → **8**, `MIGRATIONS['7']`이 사람마다 `title:null`을 채운다. `serializeState`·`applySeed`·`addNode`에 `title`. 실제 v7 저장본(10명)을 열어 v8로 올라가고(`loadFailed` null) 모두 `title:null`인 것 확인.
- **폼**: 이름 아래 「호칭 (선택 — 나에게 이 사람은)」 칸. 자동완성 49개(가족 33 + 친척·친구·동료 등). 나 자신을 고칠 때는 감춘다. 12자 제한.
- **보이는 곳**: 은하 이름표 아랫줄 "동생 · 戊 · 사막의 행성"(`nodeSub`) · 인물 패널 제목 "이름(호칭) — 戊토 일간". 관계 목록·그룹 칩·카드는 이름 그대로(호칭은 나 기준 관계라 남의 그룹 화면에선 뜻이 어긋난다).
- **가족 그룹 자동 제안**(`suggestFamilyGroup`): 저장한 호칭이 가족 호칭(아내·남편·엄마·아빠·아들·딸·첫째·둘째·형·누나·오빠·언니·동생·할머니·할아버지 등 33개)이고 아직 가족 그룹에 없으면 안내 한 줄 + 「넣기」/「아니요」. 가족 그룹이 없으면 「우리 가족」을 나와 둘로 만들어 넣는다. 강제로 넣지 않는다.
- **실측(로컬, 저장 끄고)**: 가족 그룹 밖의 사람에게 호칭 '동생'을 넣고 저장 → 이름표 "동생 · 戊 · 사막의 행성", 안내 "「동생」은 가족 호칭이에요 — 우리 가족 그룹에 ○○을 넣을까요?", 「넣기」 → 우리 가족 4인 → 5인, 패널 제목 "○○(동생) — 戊토 일간". 자가진단 **114/114**(titleField 추가).
- **고친 실수**: 패널 제목 줄에 붙인 코드 주석이 템플릿 문자열 안이라 화면에 `/* [U30] 호칭 */`로 찍혔다 — 갈무리로 잡아 뺐다.

## 그냥 진행함
- 표 입력(붙여넣기)에는 호칭 열을 안 넣었다 — 열이 하나 늘면 붙여넣기 서식 안내를 전부 손봐야 해서. 폼에서만 받는다.
- 친척 호칭(삼촌·이모·고모·조카·사촌)은 자동완성에만 두고 가족 그룹 제안은 안 한다 — 그룹 종류 「친척」이 따로 있어서.
- 이름 칸 안내를 "예: 김OO (호칭만 써도 돼요)"로 바꿨다 — 지금까지 호칭을 이름으로 써 온 사람이 그대로 써도 되게.
