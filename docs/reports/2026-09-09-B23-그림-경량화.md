## 0단계 · 착수 실측

### 지시문 전제와 실제가 다른 점 2가지

1. **테두리는 카드 한 장에 1장이 아니라 최대 2장 받는다.** 두 사람의 일간 오행이 다르면
   왼쪽·오른쪽 테두리가 달라진다. 실측한 쌍(테오↔아내)은 `border-metal` + `border-water` 둘을 받았다.
   `cardPlan()`이 내는 `keys = [...frameKeys, t.left.pic, t.right.pic]`(index.html:2608)이고
   `frameKeys`는 장마다 `'border-'+fit.key`를 밀어 넣는다(2545행).
2. **`frame.png`는 안 읽는다.** 그리기 명령의 이름이 `op:'frame'`(2593행)이라 헷갈리는데,
   그 명령이 들고 있는 `key`는 `border-<오행>`이다. `frame*.png` 4장은 좌표를 잴 때 참고한
   원본일 뿐 런타임에는 한 번도 안 받는다.

### 최종 저장 카드 기준 — 이것이 결정적이다

낱장 숫자로는 판정이 갈려서, **사용자가 실제로 저장·공유하는 카드**(캔버스 1080×1248)를
PNG 소재와 WebP 소재로 각각 그려 픽셀을 통째로 맞댔다. 같은 코드·같은 쌍·같은 캔버스이므로
차이는 소재에서만 온다.

소재는 카드에 들어갈 때 크게 줄어든다 — 그림 1696px → 칸 327~352px(**약 20%**),
테두리 1536px → 494px(**약 32%**). 줄이면서 이웃 픽셀이 평균되어 q92의 미세한 차이가 사라진다.

| 쌍 수 | 최대차 | 평균차 | 차>8 픽셀 | 차>16 픽셀 | 빠진 소재 |
|---|---|---|---|---|---|
| **18쌍** (소재 15개 전부 태움) | **16** | **0.39~0.51** | 0.004~0.014% | **0%** | **0** |

- 255단계에서 **평균 0.5단계 차이**다. 차이가 8단계를 넘는 픽셀이 만 개 중 한 개 수준이고,
  **16단계를 넘는 픽셀은 하나도 없다.**
- 테두리 5색(`border-wood/fire/earth/metal/water`)과 그림 10장이 18쌍 안에서 모두 한 번 이상 쓰였다.

분기표 B(품질 한 단계 올리기)는 발동하지 않았다. 낱장의 테두리 결 손실이 **최종 카드에서
측정되지 않기 때문**이다(테두리가 32%로 줄어드는데 잃은 결이 0.15단계짜리다).

## 3단계 · 코드 연결 — **분기표 D는 발동하지 않았다**

지시문은 "캔버스에 그리는 방식이라 되돌림을 넣기 어려우면 WebP만 쓰라"고 했지만,
이 코드는 **화면과 저장 캔버스가 같은 `Image` 객체 하나를 쓴다**(`cardAsset()`이 유일한 적재 경로,
`renderCard()`가 그 결과를 그대로 `cardPaint()`에 넘긴다). 그래서 `<img>`의 `onerror` 한 곳만
잡으면 두 경로가 함께 되돌아간다. 억지가 아니어서 **되돌림을 넣었다.**

```js
function cardAsset(key){
  if(cardPicCache.has(key))return cardPicCache.get(key);
  const p=new Promise(res=>{
    const im=new Image();
    im.onload=()=>res(im);
    im.onerror=()=>{                       /* webp 실패 — 미지원 브라우저이거나 파일이 없다 */
      const png=new Image();
      png.onload=()=>res(png); png.onerror=()=>res(null);
      png.src=CARD_B_DIR+key+'.png';};
    im.src=CARD_B_DIR+key+(CARD_ASSET_EXT||'.png');});
  cardPicCache.set(key,p); return p;}
```

`CARD_ASSET_EXT`(기본 `.webp`)는 **`cardAsset()`보다 위**에 선언했다. `let`은 호이스팅이 안 돼서
아래 두면 TDZ 오류가 나고, 그 오류는 콘솔에만 찍혀 "카드 그림만 안 뜨는" 조용한 고장이 된다
(CLAUDE.md 「전역 선언 순서 — const TDZ」, 이 저장소에서 세 번 밟은 자리). 처음에 아래 뒀다가 옮겼다.

### 되돌림이 실제로 도는지 확인했다

`CARD_ASSET_EXT`를 없는 확장자(`.webp-nope`)로 바꿔 WebP 적재를 강제로 실패시켰다.

| | 요청된 파일 | 빠진 소재 | 카드 밝은 픽셀 비율 |
|---|---|---|---|
| 되돌림 발동 | `border-water.png` · `border-metal.png` · `pic-02-pyeonin.png` · `pic-07-siksin.png` | **0** | 46.7% |
| 정상(webp) | — | **0** | 46.8% |

네 장 모두 PNG로 다시 받아 **카드가 정상으로 그려졌다.** 캔버스 크기도 1080×1248로 같다.

## 사용자 결정 필요 — 2건

1. **안 읽히는 옛 파일 86.58 MB를 지울지.** 루트의 옛 그림 10장(59.14MB) + `frame*` 4장(26.33MB) +
   `web/` 11장(1.10MB). 전부 배포에 실리지만 코드가 한 번도 안 읽는다.
   - [권장] **`web/` 11장만 먼저 지운다.** 800×993 옛 축소본이라 원본 대체물이 못 되고, 이번에 만든
     WebP가 그 자리를 대신한다. `frame*`과 옛 그림 10장은 **원본 성격이라 남긴다**(그림을 다시
     만들 때 쓴다 — 지시문의 "원본은 지우지 말 것"이 여기에도 걸린다).
   - 지운다면 git 이력에는 남으므로 저장소 크기는 안 줄어든다는 점을 함께 봐야 한다.
2. **push 시점.** B22·B23 작업분이 모두 미커밋이고 로컬이 원격보다 10커밋 앞서 있다.
   - [권장] **눈 확인 3건을 마친 뒤** 커밋 회차 → push. WebP 15장이 함께 올라간다.
