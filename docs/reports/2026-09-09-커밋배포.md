## 방법 — `git apply --cached`로 헝크 분리

`git diff index.html`을 두 벌의 패치 파일(카드용·A2용)로 쪼갠 뒤 각각 적용을 시도했다.

**1차 시도 실패** — `git apply --check <카드패치>`가 워킹트리를 기준으로 컨텍스트를 찾다가
실패했다. 이유: 워킹트리의 `index.html`은 **이미 B22·B23·A2가 전부 반영된 상태**라, 카드
패치의 "제거할 줄"(옛 `.92`/`840px` 값)이 파일에 없었다(A2 헝크까지 반영된 뒤라서가 아니라,
애초에 부분 패치를 "전체가 이미 바뀐 워킹트리"에 대고 적용하려 한 것 자체가 틀린 방법이었다).

**해결** — `git apply --cached`로 바꿨다. 이 옵션은 패치를 **인덱스(스테이징 영역) 기준**으로
적용한다 — 인덱스는 아직 `HEAD`(옛 커밋)와 같은 상태이므로, 패치가 찾는 "제거할 옛 줄"이
정확히 거기 있다. `git apply --check --cached`로 두 패치 모두 통과를 확인한 뒤,
카드 패치만 `--cached`로 적용해 인덱스에 올렸다. 이러면 **워킹트리 파일은 그대로 두고
인덱스(다음 커밋에 담길 내용)만 부분적으로 바뀐다** — `git status`에 `MM`(스테이징된 변경 +
남은 미스테이징 변경)으로 정확히 나타났다.

카드 커밋을 만든 뒤 `git diff index.html`(워킹트리 vs 새 HEAD)을 다시 재니 **A2 헝크만
정확히 남아 있었다** — 그대로 스테이징해 두 번째 커밋을 만들었다.

## 그냥 진행함

- **`index.html`을 두 커밋으로 나눴다.** `git diff` 헝크가 카드(B22·B23) 구역과
  관계 패널(A2) 구역으로 물리적으로 안 겹쳐 가능했다 — `git apply --cached`로 인덱스만

  맞았는지 확인하는 순서가 아니라, `git rev-list`·배포 md5로 확인한 **뒤에** 문서를
  고쳤다. 그 사이에 한 번 "push했다"고 앞서 적었다가 실제 push 전이라는 것을 깨닫고
  즉시 되돌린 자리가 있었다(스스로 고쳤다).

  동적 모드용인데 이 회차는 `/loop`로 시작하지 않았다 — 곧바로 취소하고 `Bash`의
  반복 `sleep`+확인 루프로 바꿨다.
