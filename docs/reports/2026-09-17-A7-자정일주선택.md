## 2. 계산 범위 — 무엇을 안 건드렸나

- **시주(조자시)는 그대로다.** 이번 선택은 **일주에만** 적용된다 — "유파 선택지는 두지 않는다"는
  옛 결정(2888행 부근)은 시주 쪽 얘기라 그대로 뒀다. 오서둔 공식은 최종 `dayIdx`(civil이든
  apparent든 선택된 값)를 그대로 참조하므로, 일주 표시와 시주 계산이 서로 어긋나지 않는다.
- **연·월주는 안 건드린다.** 절기 판정은 여전히 순수 UTC 기준이라 이 선택과 무관하다.
- **기존 사용자는 전원 무영향.** `dayRule`이 없거나(`undefined`) `null`이면 `apparent`로
  접혀 지금까지와 100% 같은 결과를 낸다(자가진단 `dayRule 기본값` 참고).

## 3. 구현 중 실측으로 잡은 것 — `est`/`dayRule`이 없는 사람 생성 경로 2곳

A5에서 `savePerson`(정보 수정 폼)의 `est` 이어받기를 고쳤지만, **사람을 처음 만드는 경로가
셋**이라는 걸 놓쳤다 — 온보딩(`ob-start`, "나"를 만든다), 여러 명 추가(`ptSave`, 표 붙여넣기),
그리고 `savePerson`의 새-사람 분기(이건 이미 `est:null` 처리가 돼 있었다). 앞의 둘은
`birth` 리터럴에 `est`/`dayRule` 키 자체가 없었다.

**실측(브라우저)**:
```
실제 온보딩으로 "나" 생성 → n.birth.est === undefined, n.birth.dayRule === undefined
(Object.keys에는 있지만 값이 undefined — savePerson이 나중에 그대로 이어받아 굳는다)
```

**분기표 발동** — "지시가 전제한 것을 코드에서 실제로 확인한다"(CLAUDE.md 착수 전 점검).
설계는 "이어받기만 하면 된다"고 전제했지만, 실제로는 이어받을 원본 자체가 비어 있었다.

**고침**: `ob-start`와 `ptSave`의 `birth` 리터럴에 `est:null,dayRule:null` 추가.
**재발 방지**: `nodeBirthFieldsExplicit` 자가진단 — 지금 로드된 사람 전원의
`birth.est`·`birth.dayRule`이 `undefined`가 아닌지 매번 훑는다.

## 4. 자가진단 (6건 추가, 79/79)

| 테스트 | 확인하는 것 |
|---|---|
| `dayRuleAmbiguous` | 자정 근처(0시)만 켜지고 23시·정오는 안 켜진다(1990-01-01 서울 기준, A4 실측과 일치) |
| `dayRule 기본값` | `dayRule`을 안 주면 `apparent`와 완전히 같다(기존 사용자 무영향의 직접 증거) |
| `dayRule=civil`(2건) | 실제로 일주가 달력 날짜 쪽으로 바뀐다 / 안 걸리는 사람은 civil을 골라도 결과가 똑같다 |
| `dayRuleMigrateV3toV4` | migrate 단계 함수가 `birth.dayRule`을 explicit null로 채운다 |
| `dayRuleBackupParse`(2건) | `'civil'`은 그대로, 모르는 값은 파일을 안 거부하고 null로 |
| `nodeBirthFieldsExplicit` | §3 재발 방지 — 로드된 사람 전원의 est/dayRule이 undefined가 아니다 |

기존 A5 테스트 `estMigrateV2toV3`도 이번에 손봤다 — SAVE_VER이 오른 뒤 `migrate()`가 체인을
계속 태워 최종 버전이 3이 아니게 되면서 낡은 기대값 때문에 실패하고 있었다(내용은 맞는데
기대값이 옛 버전 숫자였다). `MIGRATIONS['2']`를 직접 부르는 방식으로 바꿔 향후 버전이 더
올라도 안 깨지게 했다 — `dayRuleMigrateV3toV4`도 처음부터 같은 방식으로 썼다.

### 5-2. 저장·새로고침·이름만 고쳐도 유지
```
dayRule 저장 → localStorage 저장본과 메모리 값 완전 일치("civil")
새로고침 → n.birth.dayRule === "civil" 그대로
정보 수정 폼에서 이름만 바꿔 저장 → dayRule 그대로("civil"), 메모리·저장본 둘 다
```

### 5-3. 안 걸리는 사람 — 노출 안 됨, 저장값은 무해
```
같은 사람 시각을 12:00으로 바꿈 → 버튼 0개(안내 자체가 안 뜸)
저장돼 있던 dayRule="civil"은 그대로 남지만 결과에 영향 없음(§4 "안 걸리는 사람" 테스트와 일치)
```

## 그냥 진행함
- **`dayRule`을 시주(조자시)에는 안 건드렸다.** 옛 결정("유파 선택지는 두지 않는다")이 시주
  쪽이라는 걸 재확인하고 범위를 일주로만 좁혔다 — R2 §3-2도 "일주"라고만 적었다.

  아니라 같은 사주 안에서 계산 기준만 바꾸는 것이라 되돌리기 부담이 적다고 판단했다.
- **낡은 문구 4곳을 정리했다.** R2가 지적한 자리 그대로다.
- **`nodeBirthFieldsExplicit`을 "매 회차 자동 검사"로 남겼다.** 사람 생성 경로가 셋이나 되는
  구조상 앞으로 필드가 하나 더 생기면 같은 사고가 또 날 수 있어서다.
